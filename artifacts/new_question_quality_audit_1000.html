一句话判断

最核心的问题不是“有几条曲线不好看”，而是生成器把很多题做成了可重复、可混杂、训练还没结束的比较。
01最明显：分类题中 spiral / XOR 占 333/499，且 451/499 只有两个有效特征，任务几何比较集中。
02最影响可解释性：optimizer-only 几乎总是同时改变算法、学习率和正则化；architecture-only 也常同时改变深度、宽度、残差和归一化。
03最影响训练可信度：364 道题有至少两个选项在最后一段仍明显下降；47 道回归题至少两个选项不如常数预测。
04最影响多样性：1000 道题只有 43 个数据集实例，795 道题落在被重复使用至少20次的数据集上。

问题卡片

红色 = 建议优先修复；黄色 = 明显质量风险；蓝色 = 需要确认设计意图。

01 · TRAINING

很多题在训练结束前还没有收敛

约 364 / 1000

用最后 10% 曲线与前一个 10% 比较，至少两个选项仍下降超过初始量级的 1%。更严格地用 2% 时仍约 158 题。这样的题容易把“训练预算不够”误当成“模型更差”。

代表：q_32d29e、q_5f3c6f
02 · CLASSIFICATION

分类题出现成片的“接近随机”选项

132 / 499 分类题

至少两个候选的最终 test CE ≥ 0.65，约 26.5%；用更严格的 0.68 仍有 79 题。尤其集中在 spiral（65题）和 XOR（42题），题目常变成比较谁训练失败得更少。

代表：q_011b16、q_0adfc7
03 · REGRESSION

至少两个选项还不如“永远预测均值”

47 / 334 回归题

以测试标签方差作为常数预测基线，至少两个候选的 MSE ≥ 1 倍基线方差。宽松地用 0.8 倍则有 91 题；严格问题主要集中在 univariate（45题）。

代表：q_34bf13、q_10da39
04 · DATA DIVERSITY

数据集实例重复使用，题目独立性不足

795 / 1000 题重度复用

1000题只有 43 个数据集实例；有 27 个实例各自被至少20道题使用，覆盖 795 道题。最多的单个实例被使用 62 次，另一个被使用 54 次。题目不完全重复，但数据分布并不独立。

最多复用：mvar_021157 · 62题、sym_732c72 · 54题
05 · CANDIDATE REUSE

不同题目之间复用了同一个候选

222 / 1000 题

3000个选项位置中有 427 个是重复candidate，涉及 155 个candidate；222道题至少包含一个在别题出现过的候选。若模型记住某些设置或题面模式，会削弱题库的独立性。

最多重复的单个candidate出现在同一批 bigram / univariate set 中，最高重复16次。
06 · QUESTION STABILITY

部分正确答案对随机种子不够稳定

119 / 1000 题

按题目记录的 10 个 seed，119题的均值winner没有10/10胜出；其中 22题只有 8/10 或更低。它们可能通过当前 gate，但更像“统计上勉强可分”而不是稳定结论。

全题 win-rate：881题为1.0，97题为0.9，19题为0.8，3题为0.7。
07 · SYNTHETIC TARGET

一元回归里有不少退化成常数或直线的函数

约 40 / 167 一元回归题

7个一元函数实例中，19题对应的表达式实际上是常数，另有21题是仿射函数。它们不太像丰富的函数逼近任务，更容易测试优化器能否找到一个简单解。

代表：sym_246f37: x / -1.6667 / abs(x) * 1；sym_7d3ae1、sym_b2a2ca 为线性形式。
08 · SYNTHETIC TARGET

多元回归存在真正没被使用的输入维度

约 22 / 167 多元回归题

至少两个数据集的表达式含有被乘以 0 的特征项，且该特征没有在别处出现：mvar_416509 被19题使用，mvar_d5bab9被3题使用。题目名义上是多元输入，实际有效维度更低。

代表：tanh(2*x2) * 0、x0 * 0。
09 · CLASSIFICATION DIVERSITY

分类几何过度集中在 XOR 和 spiral

333 / 499 分类题

两个规则合计占 66.7%；451题的有效特征数是2，占90.4%。另外三个规则只有 sparse_interaction 69题、smooth_additive 64题、piecewise_boundary 33题，任务形态不够均衡。

所有分类数据集的 spiral_turns 都是2.0；这会进一步减少几何多样性。
10 · ARCHITECTURE AXIS

architecture-only 往往同时改了很多架构因素

246 / 400 题

这些题同时改变 depth、residual、layer_norm 和 activation，宽度有时也一起变。题型名称虽然只说“模型架构”，但无法回答“到底是深度、残差还是归一化带来了差异”。

另有331/400题改变 depth，285/400题改变 width；这是复合架构比较，不是单因素实验。
11 · OPTIMIZER AXIS

optimizer-only 把算法和超参数绑在了一起

292–300 / 300 题

292题改变优化器类型，293题改变 lr，288题改变 weight_decay；108题同时改变 type、lr、weight_decay、momentum 和 betas。模型答对后，无法知道是在识别算法，还是在识别某个学习率。

这不是“只变一个 optimizer 配置字段”，而是多个 optimizer 子字段共同变化。
12 · MIX COMPOSITION

mixed 题内部其实不是同一种 mix

300题中仅83题三轴全变

151题变 model+optimizer，83题变 model+optimizer+loss，66题只变 optimizer+loss。三类题都叫 mixed，但候选差异的组合不一致，模型可能利用“哪些轴出现”这一题型线索。

66/300题的 mixed 甚至不改变 model；151/300题不改变 loss。
13 · CAPACITY SCALE

有些比较实际是在比较参数量悬殊

100 / 1000 题 ≥10倍

100题的候选参数量最大值/最小值至少10倍，22题至少100倍。另有339题出现至少一个候选参数量/训练预算≥10的情况。这样的题容易把“大模型通常更能拟合”当成架构洞察。

极端例子：q_b62abc 的参数量比为638倍。
14 · LATE REBOUND

一部分题有较明显的后期反弹

约100 / 1000 题

至少两个选项在曲线中先达到更低值、之后又反弹超过初始量级的2%；用5%的严格阈值仍约25题。少量异常不算问题，这里关注的是成组出现的后期退化。

其中分类题约65题，回归题约17题；建议和训练预算、weight decay一起复核。
15 · GT COMPLETENESS

有候选只完成了部分 seed

20 / 1000 题

20道题包含 failed_seeds=1 的候选。当前质量过滤允许最多一个失败 seed，因此它们仍进入题库；这未必是题目设计缺陷，但会降低曲线和均值的可信度。

失败候选不应被当作普通高方差结果，建议单独标记或重新运行。
16 · ARCHITECTURE DIVERSITY

architecture-only 的模型家族分布偏窄

333 / 400 题全是 MLP

333题的三个选项都是 MLP；35题是 Transformer LM，剩余32题才包含 GRU/Transformer 混合。若目标是泛化到“架构推理”，大量题其实只覆盖 MLP 的深度、宽度和残差变体。

这可能是按 family 约束的合理结果，但应在报告中明确它不是跨模型家族评测。
17 · SEARCH SPACE

架构搜索维度较固定，模型差异重复在少数字段

depth / width 主导

400题 architecture-only 中，depth在331题变化，width在285题变化；leaky_relu_slope没有任何题发生变化，model spec中也没有 dropout 这一维。若希望考更广泛的架构理解，当前覆盖面偏窄。

这是多样性问题，不等同于实现错误；需结合产品目标决定是否扩展模型池。

审查口径与修复建议

这里的判断是质量审查，不是对模型分数的重新评估。

先修生成器和筛选规则，再重新生成题库。

我是怎样判定“欠训练”的

对每个候选的10-seed平均 learning curve，比较最后10%与前一个10%。若最后一段仍比前一段下降超过初始曲线量级的1%，记为宽松信号；题目中至少两个候选满足时计入。2%作为更严格版本。

我是怎样判定“过拟合/后期退化”的

计算最终曲线相对历史最低点的反弹幅度，并用初始曲线量级归一化。至少两个候选超过2%才计入；5%只用于寻找更强的成组模式。单个尖峰没有被单独列为问题。

我是怎样判定“接近随机”的

分类题使用最终 test CE。二分类均匀随机的 CE 约为 log(2)=0.693；因此 CE≥0.65是宽松提醒，CE≥0.68是更严格提醒。计数要求至少两个候选满足。

我是怎样判定“回归不如常数”

用测试标签方差作为常数预测的 MSE 基线。MSE≥1.0倍基线是严格提醒，MSE≥0.8倍是宽松提醒。只要至少两个候选达到阈值，就认为这道题的训练质量值得复核。

最建议先修的四件事

  • 重新生成目标函数前做符号/数值简化：拒绝常数、线性、死特征和极端动态范围。
  • 生成题目时加入 per-question curve quality gate：至少两个选项不能都在末端显著下降。
  • 把 optimizer algorithm、lr、weight decay 的实验拆开，或在题目里明确它们是一个“完整优化器配置”。
  • 限制数据集与candidate跨题复用，至少在 train/test split 或 question split 层面做独立性审计。

哪些现象没有被列为问题

  • 少量病态曲线、单个候选失败或一次异常反弹，没有单独算作系统性问题。
  • 总样本预算在每道题内部是一致的：1000/1000题没有发现 choice 间 total_samples_seen、batch_size 或 training_steps 偷偷变化。
  • 正确答案位置基本均衡：A=327、B=339、C=334，不像是答案位置偏置。
  • 不同题共享同一候选集不等于题目完全重复；这里把它作为多样性风险，而不是直接判无效。
