Feature contract

数值 condition 与类别 condition 如何进入同一个模型

输入单位是一条 candidate setting；target 只来自执行生成代码后保存的 mean_loss，任何 answer、GT 路径或 target 字段都不进入特征编码。

数值 condition

learning rate 使用 log10(lr)；budget 与 batch size 使用对数；MLP 编码 depth、log2(width)、residual、激活/LayerNorm 的数量、比例与转移次数；Transformer 编码 d_model、d_ff、层数、heads、head dimension 和比例/乘积。

参数量使用唯一尺寸列 derived.log_total_params，避免同时输入 raw total/trainable counts 造成重复权重。

类别 condition

optimizer.type、loss_id、model.type 以及 full 特征中的逐层 activation 等字符串，由 DictVectorizer 在每个训练 fold 内学习 one-hot 词表；推理时未见类别不会扩展词表。

显式增加 optimizer × log10(lr) 列，让线性模型也能表达“同一个 LR 在 Adam 与 RMSprop 下意义不同”。

混合与模型

数值列与 one-hot 列进入同一个 dense matrix；常量列在 fold 内删除，随后统一标准化。Ridge / ElasticNet 学加性规则；polynomial Ridge 显式增加二阶交互；tree、RF、ExtraTrees、GBDT、XGBoost 与 MLP 学非线性交互。

模型始终按 family 训练；所谓“统一 XGBoost”是三个 family 使用同一种算法，但仍各自拟合，避免把 CE 与 MSE 的尺度硬混在一起。

参数量 provenance

“手算参数量”不是脆弱的纸面公式：训练侧实例化 GT 真正调用的 generated Model 并统计 parameters().numel()，再与 registry 构建模型交叉校验；不一致就拒绝导出。

无参数量消融同时让 encoder 忽略该列，并在老 60 external 输入准备阶段完全不生成 total_params / log_total_params。

“不允许参数量”不等于“不允许规模代理”

消融只删除精确参数量列；width、depth、d_model、d_ff 仍是合法架构 condition，所以模型仍可能重建近似 size signal。报告回答的是“精确参数量特征的边际价值”，不是把所有容量信息都抹掉。

方法定义

启发式公式 / 线性启发式 / meta-model 的输入都是候选的 architecture 与训练 setting：模型类型、层数、宽度、残差、LayerNorm、optimizer、learning rate、weight decay、loss、batch size、budget，以及派生特征。总参数量是所有预定义自变量中的核心基线特征。

输出可以是预测最终 loss，也可以只用于候选间排序。零拟合公式不读训练标签；线性校准只拟合少量系数；Ridge / polynomial Ridge / tree / XGBoost / MLP 则在 family 内 train split 上学习 setting→loss 映射，再在 validation、external old-60 或 OOD 切分上评估。

Case-driven analysis

数字背后的现象：容量、学习率、反馈恢复和记忆检索

以下不是额外重算 GT；它们来自 artifacts/quiz_attempt_60/context_analysis/case_atlas.json 和原始 case assets。目的是把表格分数翻译成可解释的失败/恢复模式。

Case 1 · q_094b12：容量 shortcut 成功，高学习率是陷阱

Bigram LM 混合题。正确项 A 是最大参数量 transformer，Adam 3e-4，test CE 3.2415；诱饵 B 是 RMSprop 1e-2，CE 3.4671。这类题解释了为什么“最大参数量”这个粗规则能到 40/60，而“最高学习率”只有 22/60。

现象不是“越大永远越好”，而是在旧 60 的短预算生成器里，容量收益经常比过热 optimizer 的早期速度更可靠。

Case 3 · q_44d7aa：盲答共识错在 Adam 3e-3

同一 bigram 数据集上，正确项 B 是 RMSprop 1e-3、309k 参数、CE 3.3775；C 同样 309k 参数但用 Adam 3e-3，CE 反而到 3.5971。单题盲答 3/3 都选 C；整套盲答 19 个记录中 14 次选 C；全程反馈也只有 3/18 次修正到 B。

这是“合理先验难以修正”的 case：模型知道短预算需要快，但把 3e-3 当成甜点，实际已经过热。

Case 18 · q_f241b4：整套横向比较强化了错误容量先验

正确项 B 只有 93,408 参数，最大模型 A 有 407,712 参数。单题盲答反而 3/3 正确；整套盲答 19/19 都改选 A；全程反馈恢复到 13/18。

这说明更多上下文不必然更好：当横向比较形成“这一族大模型通常赢”的强 prior 时，局部反例会被系统性压掉。

Case 44 · q_59c2dc：capacity trap 的直接反例

最大模型 B 的 MSE 为 0.2952，较小的 SGD 候选 C 为 0.2269。单题盲答 0/3、整套盲答 2/19、全程反馈 12/18。

参数量规则能到 66.7%，但这类题说明它不是稳健机制；optimizer 与架构的配合可以让更小模型在固定短预算内领先。

Case 46 · q_70b2fe：univariate 是 hard family，但反馈能拉回

单题盲答三模型都选 A，正确项 C 是 99,969 参数、Adagrad 1e-2，MSE 0.1076；A 的 MSE 是 0.2817。整套盲答 19 个记录里只有 4 次选 C，但 grouped feedback 为 2/3，全程 feedback 为 18/18。

这说明 univariate 的单题困难不只是模型弱，而是人类直觉和 LLM 先验都容易低估某些大容量/非 Adam 组合；一旦同一数据族的反馈累积起来，错误会被快速校准。

Case 60 · q_ff5ef6：最后阶段更像 candidate memory

正确项 A 是 Adagrad 3e-4、331,777 参数，MSE 0.0232；B/C 都是 1,169 参数且高学习率，MSE 分别 0.1476 / 0.1786。单题盲答 0/3，整套盲答 7/19，但 grouped feedback 3/3、全程 feedback 18/18。

Literature Framing

这不是静态 leaderboard，而是长上下文行为学测量

本报告的解释框架来自长上下文利用、many-shot ICL、verbal feedback memory 和 self-feedback refinement；文献只用于概念边界，不替代本实验数据。

Long-context fragility

Lost in the Middle 与 RULER 提醒我们：长上下文不是均匀可用的外部内存，位置和检索形式会改变表现。

Many-shot ICL

Many-Shot ICL 支持“更多同类上下文可提升模式归纳”的方向，但本实验还要把模式学习和 exact candidate memory 拆开。

Verbal feedback memory

Reflexion 和 Self-Refine 说明自然语言反馈可作为测试时学习信号；这里的 lesson 同时含抽象规则和具体 metric。

Task induction

ICL latent-variable view 给了一个解释：模型可能在上下文中更新“这个题集奖励什么”的隐变量，而不只是逐题独立推理。

Agent review protocol

下一轮若真用 100 个 reviewers，应先喂标准 case packet：60 个逐题 reviewer、20 个 cross-case reviewer、10 个统计复核、10 个文献写作复核，输出固定 schema。

论文口径

主张应写成“context setting 改变了解题行为和可用证据”，而不是“某模型绝对更聪明”。本报告的强结论来自同一模型跨 setting 的变化。

共同偏差会让投票失效

6 个整套 agent 在 44/60 题上答案完全一致，其中 26 题六个一起答错；平均每题的最高票达到 5.52/6。多数投票仍只有 24/60 = 40.0%，说明这不是采样噪声，而是同一个系统先验被独立复现。

反馈后能明显恢复

公平重测已消除连续性疑点

Behavioral interpretation

为什么不同上下文会改变正确率

这更像行为学测量，而不是一个静态 leaderboard。
单题盲答
只能调用一般先验
模型只能根据 optimizer、学习率、模型容量等常识猜测；无法知道本题集生成器的具体偏好。
整套盲答
可以做横向比较
同一候选、相似数据族、重复配置会在多题中出现；模型能用题间一致性校准自己的启发式。
顺序做10题
开始形成经验规则
模型只能在当前 10 题内积累 lesson；小组之间 reset，所以它能学习，但记忆长度受限。
顺序做全部题目
最接近人类刷题视角
一个 agent 从头做到尾，前面题目的反馈都可以进入后续推理；记录器强制版只是在工具层保证先答后看。
长上下文
有收益，也有衰减风险
整套接龙会变长；但 subagent 具备自动上下文管理，主要风险不是上下文压缩 bug，而是协议审计不够硬。

正式结论要同时报告 subagent 可见上下文、禁止项、输出 JSON schema、模型 effort 和评分方式。

这组实验最有价值的不是单个分数，而是展示 GPT 的“解题行为”会被上下文设置显著调制： 从单题先验、到整套比较、再到反馈学习，表现呈现可解释的阶梯式变化。
