ArchitectureIQ · Quiz Frontend

前端工作总结

人可玩的静态 quiz：读 BakeFile JSON、三阶段做题、揭晓曲线与 Good/Bad 反馈，并上报 telemetry。 不跑训练、不读原始 pipeline 产物。

branch: quiz-frontend HEAD: b4a493e site: architecture-iq.com updated: 2026-07-31

1. 目标与边界

做什么 把后端导出的 bake 题包做成可分享的人机对照入口，采集答题与「是否好题」信号。
不做什么 不开放自定义训练 / Reflect；不直连 dataset 文件夹；Streamlit 旧 UI 冻结。
分工 前端只改 frontend/quiz/；题包与 schema 在 contracts/ + 导出脚本。

2. 技术架构

栈： React + TypeScript + Vite · 静态托管（Cloudflare Pages）

  • 入口数据：public/data/questions.json（BakeFile，当前 demo ~46 题）
  • 契约：contracts/quiz_bake.schema.json，可用 tools/validate_quiz_bake.py 校验
  • 核心源码：src/main.tsx（UI + 流程）、types.ts、telemetry.ts、styles.css
  • 遥测：Supabase Edge Function（Bearer key）；失败不影响做题
Home · Begin → Observe · Dataset → Compare · Choices → Reveal · Curves + Vote → Next / Questions

3. 产品行为（考试模式）

  • Begin：清空本场答题与反馈，换新 session_id，从第 1 题开始。
  • 不可重答：已答题目只能回看 reveal；未答可继续作答。
  • Questions 列表：每题状态 Unanswered / Correct / Wrong；标题仅 family · type。
  • Questions → Back：跳到第一道未答题；全部答完则回到进入列表前的题。
  • 左上 ArchitectureIQ：回主页（不重置）；再次 Begin 才重置。
  • Next：前进下一题；有序题到末题显示 End。
  • Good / Bad：揭晓后评价「是否好题」，投票即继续（带文案 Rate the problem to continue）。

4. 界面与可视化

题目页

  • 标题栏：family · question type（metric 下沉到 Dataset panel 的 Target metric）
  • Dataset：参数、示例、可视化；See choices 右对齐
  • Choices：文案简化为 “Choose the better model.”
  • Reveal：对错 verdict + learning curves + Good/Bad

Learning curves

  • 主图 + 下方 可拖动区间（左右手柄缩放、中间平移）；Y 轴按可见区间 min/max 缩放，避免早期尖峰压平曲线
  • Bake 含逐步 std 时绘制 mean ± std 色带（当前 46 题题包均有 multi-seed std）
  • Reset range：退出缩放

5. Telemetry

环境变量：VITE_TELEMETRY_URL、VITE_TELEMETRY_KEY

event_type用途
session_startBegin 后首次进入考试
question_view进入某题
stage_changeobserve → compare → reveal
answer_submit锁定选项
question_leave未答离开
audit_feedbackGood/Bad（含 is_good_problem、vote、对错等）

6. CI 与部署

  • Workflow：任意 push 仍跑 Frontend build / Node 22
  • quiz-frontend 与 frontend/* 分支跳过 Python / Ruff / pytest，避免无关失败邮件
  • 生产：Cloudflare Pages 从 frontend 构建产物发布；站点 architecture-iq.com
