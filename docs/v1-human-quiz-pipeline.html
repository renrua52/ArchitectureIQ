从 LLM Benchmark 到人类在线题：整套流程总结

给同事对齐：后端如何造题与评测 LLM，如何筛出人类可玩子集并 bake； 前端如何考试式交付、部署上线，以及揭晓页展示 LLM 思维链。

backend: quiz-backend frontend: quiz-frontend site: architecture-iq.com bake: 250q · V1 human pre-review updated: 2026-08-04

一句话

我们先在 v1 profile 上规模化生成「数据 + 候选设定 + GT」选择题，用多模型 LLM 盲测得到难度/对错矩阵； 再按人类可读 bucket（univariate / xor / spiral / bigram）分层抽约 250 道三选一题，导出 BakeFile； 前端静态站加载题包做人测，并在答完后展示「做对此题且成功提取 CoT」的 LLM 思维链。

端到端流水线

1 · 造题库→ 2 · LLM 评测→ 3 · 打难度标签→ 4 · 人类子集策展→ 5 · Bake 导出→ 6 · 前端上线

1. 后端：造 LLM Benchmark 题库

分支：quiz-backend · 主要工具 tools/benchmark_v1_build.py 等

  • 统一 v1 池：覆盖 univariate / 分类（含 XOR、spiral）/ bigram 等 family，以及兼容模型类型。
  • 流水线仍遵守仓库不变量：spec → 生成代码 → 执行 → GT（不另写平行训练逻辑）。
  • 生成三选一题，写入 benchmarks/v1_llm/questions/q_*/（含 question.json、prompt、候选路径等）。
  • 题带 benchmark 元数据（bucket、budget tier、gap 约束等），便于后续分层。

2. 后端：LLM 评测

工具：tools/benchmark_v1_llm_eval.py + tools/llm_eval/

  • 对各模型跑盲测，结果落在：
benchmarks/v1_llm/llm_runs/{model}/results/{question_id}.json
  • 关键字段：correct、parsed_letter、chain_of_thought、message_parts.reasoning_content、model_response 等。
  • 参与共识的模型约十余个（如 DeepSeek / Qwen / Claude / GPT / Gemini / GLM…）；部分模型（如 Kimi-K3、grok-4.2）不进共识。
  • 矩阵与报告：llm_results_matrix.json、llm_report.html 等。

3. 后端：难度标签

工具：tools/benchmark_v1_tag_difficulty.py

  • 按多模型对错做 consensus_v1，写出 benchmarks/v1_llm/llm_difficulty.json。
  • 每题得到：llm_difficulty（easy/medium/hard/very_hard）、llm_consensus_acc、llm_outcomes 等。

4. 后端：人类题策展 + Bake

工具：tools/benchmark_v1_curate_human.py → 调 export_quiz_static.py → validate_quiz_bake.py

筛选原则 只保留人类可读 bucket：univariate、xor、spiral、bigram；按 type / 难度 / budget 分层抽样，目标约 250 题。
产物 benchmarks/v1_human/questions.json（BakeFile）+ manifest；注入 llmDifficulty、llmConsensusAcc、track=human_{bucket}_{diff}、llmCot。
契约 必须符合 contracts/quiz_bake.schema.json。前端只吃 BakeFile，不读原始 q_ 目录。

5. 前端：人类考试站

分支：quiz-frontend · 目录 frontend/quiz/ · 站点 architecture-iq.com

产品行为

  • Begin 开一场考试：清空作答，新 session；题目不可重答，可回看已答。
  • Questions 列表显示 Unanswered / Correct / Wrong；Back → 第一道未答。
  • 左上品牌回主页（不重置）；再次 Begin 才重置。
  • 揭晓后 Good / Bad（好题投票）兼作继续；telemetry 上报 audit_feedback 等事件。
  • 三阶段：Dataset → Choices → Reveal（曲线 + 投票 + LLM CoT）。

可视化与体验

  • 学习曲线：可拖动 sample 区间，Y 轴按可见范围缩放；有 std 时画 multi-seed mean±std 色带。
  • 揭晓页最下方：展示做对此题且成功提取 CoT 的模型思维链；若无人做对 → Real hard problem, no LLM gets it right!

部署要点

  • Cloudflare Pages 单文件上限 25 MiB；整包 bake ~37–39 MiB。
  • build 后 scripts/split-bake.mjs 拆成 index.json + by-id/*.json，前端按题懒加载。
  • FE-only 分支 CI 只跑 frontend build，跳过 Python job，避免无关失败邮件。

7. 给同事的「怎么继续」

# 后端：策展并 bake（需本机已有 llm_runs / questions）
cd quiz-backend worktree
python tools/benchmark_v1_curate_human.py   # 内含 export + validate + llmCot 注入

# 前端：放入题包并上线
cp benchmarks/v1_human/questions.json → frontend/quiz/public/data/questions.json
# 或：python frontend/quiz/scripts/enrich-llm-cot.py --bake ... --runs ...
cd frontend/quiz && npm run build   # 自动 split-bake
# Cloudflare Pages 跟踪 quiz-frontend，push 后 redeploy
