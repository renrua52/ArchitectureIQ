ArchitectureIQ · branch side/tabpfn-settings · generated candidates (not frozen packs)

Settings → metric：按 dataset family 生成并评估 TabPFN

假设：把 ArchitectureIQ 的 candidate settings（模型 / 优化器 / 损失 / budget）编成表格行，在随机采样并跑完 GT 后， TabPFN 能从 held-out settings 预测 selection metric（绝对误差 + 排序）。本报告记录一次完整的 create-dataset → generate-candidates(GT) → 建表 → 5-fold 回归评估 实验。

1. 整体 pipeline（端到端）

编排入口：experiments/tabpfn_settings/scripts/run_family_pipeline.py。 对每个 family 独立跑完下面 5 步；family 之间不共享数据实例，也不把不同 family 的行混进同一次 TabPFN fit。

Create dataset instance

调用 architecture_iq.datasets.create_dataset(profile, seed, family_name=…)。

  • 从 profile dataset_configs.{family} 采样/固定合成参数，写入 dataset_spec.json
  • 渲染并执行 synthesize.py，物化 train/test（及 family 额外文件）到 data/datasets/{family}/{dataset_id}/
  • dataset_id 内容寻址：同 family + seed（+ options）可复现同一实例

Sample random candidates (settings)

调用 architecture_iq.candidates.sets.generate_candidate_set(...) （脚本层也可用 sample_random_settings.py）。

  • 在 profile pools 上采样：本次 varying_axes={model, optimizer}，loss 轴固定为 family 默认池采样结果中的不变量
  • 每个 candidate 写成 candidate_spec.json，再经 write_candidate 渲染 model.py / optimizer.py / loss.py / train.py
  • 共享 budget：同一 set 内所有 candidate 的 total_samples_seen 相同（见下表）
  • 输出目录：.../candidates/set_{budget}_var_var_fix_{hash}/c_{id}/

Ground truth（必须执行生成代码）

run_ground_truth：先 _sync_candidate_files() 从 spec 重渲染 .py，再 import train.py → train_and_eval()，在 n_seeds=3 上跑完，写入 results/summary.json + curves.npz。

  • 标签不是手写训练环；与 prompt/benchmark 公平性同一不变量：spec → code → run → metrics
  • 失败/非有限 metric 的行在建表时丢弃（故 N 可能 < 40）

Build tabular settings table

encode_spec(candidate_spec, summary)（src_tabpfn_settings/features.py） 把每个有 GT 的 candidate 压成一行 CSV。

  • 不做 question 组装；不用 frozen pack；一行 = 一个 setting + 一个 GT 标量
  • 跨 model_type 的字段用 NaN 对齐（如 KAN 的 residual 空、Transformer 的 grid_size 空）

Fit predictors & evaluate (layer B)

scripts/evaluate.py：5-fold CV，比较 train_mean / Ridge / HistGB / TabPFNRegressor v2.5。

  • 指标写到 artifacts/generated/report_{family}.json；本 HTML 由这些 JSON + CSV 汇总
profile YAML → create_dataset → dataset_spec + synthesize.py → 物化数据
pools 采样 → candidate_spec → model/loss/optimizer/train.py → GT summary

2. 输入 X / 输出 y / 两层「训练」

必须分清的两层

  1. 层 A — ArchitectureIQ candidate GT：对每个 setting 真正训练神经网络（generated train.py），得到 mean_test_mse 或 mean_test_ce。这是标签来源。
  2. 层 B — TabPFN / 基线回归：把 settings 当表格，用部分行预测 held-out 行的 metric。 TabPFN 的 fit 不梯度更新 foundation 权重，只是把训练折 (X,y) 当作 in-context 条件。

输入 X（一行一个 candidate）

特征来自 candidate_spec.json 扁平化，绝不包含 summary 里的最终 metric、曲线或 seed 统计（避免泄漏）。

组字段说明
规模model_type, trainable_parameter_count, log_params模型族与参数量
Budgetbatch_size, training_steps, total_samples_seen同 set 内 samples_seen 固定；batch/steps 由 budget 与采样 batch 决定
Optimizeroptimizer_type, lr, log_lr, weight_decay, momentum本次 vary；momentum 仅 SGD 有值
Lossloss_id, loss_lambda本次不 vary；多数行为常数
MLP/KANdepth, width, residual, layer_norm_frac, activation_primary, grid_size, spline_order, base_activation回归 / XOR-style tabular
LMd_model, num_layers, num_heads, d_ff, layer_residualbigram；encode 时 depth←num_layers、width←d_model（冗余）

预处理：全空列丢弃；bool+NaN（如 residual）映射成字符串类别，避免 TabPFN/sklearn 对 pandas.NA 报错。 Ridge/HGB：数值列 median+标准化，类别列 most_frequent+one-hot。

输出 y

  • 回归族：mean_test_mse（越小越好）
  • LM / 表格分类：mean_test_ce（越小越好）
  • 来源：results/summary.json 中 GT seeds 的均值；与 family selection_metric 对齐
  • 模型输出：标量 ŷ（回归），解释为「该 setting 的预测 test metric」

3. 交叉验证与基线协议

项设定
样本单位candidate 行（不是原始数据 token / 原始回归样本）
划分KFold(n_splits=5, shuffle=True, random_state=0)
泄漏每个 candidate 只进一个测试折；报告指标为 OOF 拼接
TabPFN「训练样本量」每折 n_train（约 28–32）；不是 foundation 预训练规模
train_mean预测全集 y 均值（无结构基线；Spearman 无定义）
Ridgeα=1 + 上述 ColumnTransformer
HistGBmax_depth=4, max_iter=200, random_state=0
TabPFNTabPFNRegressor.create_default_for_version(V2_5)，device=cuda
指标MAE、RMSE、Spearman ρ、pairwise ranking accuracy（所有 y_i≠y_j 对上，预测序是否与真值序一致；越低越好的 metric）
