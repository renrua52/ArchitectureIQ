ArchitectureIQ · side/tabpfn-settings · Phase P0 · XOR + GRU packs

TabPFN 输入 / 输出 / 训练测试协议 & 全 pack 结果

本报告把「一行是什么、模型吃什么、吐什么、怎么划分训练测试」写清楚，并在当前分支已有的两个 frozen question pack（XOR、GRU）上分别跑完 5-fold CV。

0. 问题定义（先分清两层「训练」）

层 A — ArchitectureIQ candidate 的 GT（标签从哪来）

每个 candidate 已有 candidate_spec.json + 执行生成的 train.py 得到的 results/summary.json。标签是 summary 里的 mean_test_ce（GT seeds 上的均值）。本实验不再重新训练这些 candidate。

层 B — TabPFN / 基线的「监督回归」（本报告评估的对象）

把每个 candidate 编成一行表格特征 X，标签 y=mean_test_ce。在 candidate 集合上做交叉验证：用一部分行拟合预测器，预测 held-out 行的 CE。

TabPFN 特别说明：fit 不会用梯度更新 foundation 权重；它把训练折的 (X,y) 当作 in-context 条件。预训练权重固定为 Prior-Labs TabPFN-2.5 regressor checkpoint。

candidate_spec.json → encode_spec() → 特征行 X
results/summary.json → mean_test_ce → 标量标签 y
KFold 训练折 (X_tr, y_tr) → TabPFN.fit / Ridge.fit / …
测试折 X_te → predict → ŷ_te ；与 y_te 比 MAE/RMSE/Spearman/pairwise

1. 输入 X：包含哪些信息？

每一行 = 一个 ArchitectureIQ candidate。特征来自 candidate_spec 的扁平化（见 src_tabpfn_settings/features.py），不含曲线、中间 loss、或任何 test metric 泄漏字段。

特征字段设计（全局 schema）

组字段含义
身份/规模model_type, trainable_parameter_count, log_params模型族 + 参数量
Budgetbatch_size, training_steps, total_samples_seen训练日程；P0 内各 pack 为常数
Optimizeroptimizer_type, lr, log_lr, weight_decay, momentumP0 内 Adam/lr/wd 常数；momentum 全空
Lossloss_id, loss_lambdaP0 内 cross_entropy；lambda 空
MLP / 共享 depth-widthdepth, width, residual, layer_norm_frac, activation_primaryXOR-MLP；KAN 也复用 depth/width
KANgrid_size, spline_order, base_activation仅 KAN 有值
LMd_model, num_layers, num_heads, d_ff, layer_residualGRU pack；encode 时 depth←num_layers、width←d_model（冗余）
未编码但仍存在于 spec 的字段（当前实现省略）： XOR — input_dim/output_dim/grid_range/variant/leaky_relu_slope（本 pack 内多为常数）； GRU — vocab_size=32、context_length=16（全表常数，省略不影响 within-pack CV）。

2. 输出 y：是什么？

  • 主目标：mean_test_ce（越小越好）
  • 来源：GT runner 执行 candidate train.py 后写入 results/summary.json 的均值，与 ArchitectureIQ selection metric test_ce 对齐
  • 模型输出：一个标量 ŷ（回归），解释为「该 setting 的预测 test CE」
  • 不是分类：不用 TabPFNClassifier；不做 question 对错预测

3. 训练 / 测试细节（层 B）

项设定
样本单位candidate 行（不是 token、不是原始 XOR/语言模型样本）
划分sklearn.model_selection.KFold(n_splits=5, shuffle=True, random_state=0)
泄漏防护每个 candidate 只出现在一个测试折；报告指标均为 out-of-fold 拼接
TabPFN「训练样本量」每折 n_train（见下表）——即 in-context 条件行数；不是 foundation 预训练规模
测试样本量每折 n_test
基线 CVRidge / HistGB 用同一套 KFold（cross_val_predict）
train_mean用全集 y 的均值作常数预测（无信息上界参考；Spearman 无定义）
TabPFN 版本 / 设备v2.5 regressor default ckpt · CUDA A100 80GB
预处理（TabPFN）库内置；我们额外把 bool+NaN 列映射成字符串类别
预处理（Ridge/HGB）数值：median impute + StandardScaler；类别：most_frequent + OneHot
评价指标MAE、RMSE、Spearman ρ、pairwise ranking accuracy（所有 y_i≠y_j 的无序对上，预测序是否与真值序一致；CE 越低越好）

8. 局限

  • P0 用的是 question pack 里已筛过的 candidates，不是均匀随机 settings
  • optimizer / loss / budget 常数 → 测的是「架构→CE」，不是完整 setting 向量
  • N 仍然很小（63 / 48）；fold 测试集只有 ~10 行
  • GRU 表存在 depth/width 与 num_layers/d_model 重复编码
  • 下一阶段 P1：同 dataset 上随机采样大量 settings + 跑 GT，再评估
