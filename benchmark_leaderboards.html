⏱️ Single Training Run Cost — Not the Bottleneck

Key insight: The 24h budget in MLE-bench is not about single training runs being slow — it's about repeated trial-and-error. Individual training runs on these tasks are actually very fast.

A single training run is fast enough. On GPU, most Low-complexity tasks train in 1–5 minutes. On CPU, tabular tasks are still under a minute. The 24h budget went to 500 iterations of trial-and-error, not to one long training run. This means the "probe-only" paradigm (run a few quick experiments, then decide) is perfectly feasible.

🎯 A New Paradigm: Offline Results + Probe-Only Experiments

Three tiers of information available to the model
TierWhat the model seesBudgetPurpose
1. Offline Results Pre-computed training curves, loss trajectories, final metrics for several candidate architectures on the dataset. Pre-generated by us — the model never trains these. 0 GPU time (for the model) Gives the model "experience" with the dataset without running code. Mirrors what a human sees: someone else already ran baselines.
2. Probe Experiments The model can request limited, small-scale training runs — e.g. "train this architecture for 100 steps on CPU" or "verify that this loss function converges." Max ~5 probes, each ~1 hour CPU / a few min GPU. ~5 probes × few min GPU Allows the model to test specific hypotheses without full engineering. This is the "intuition probe" — not a grid search.
3. Full Engineering (forbidden) Autonomous 24h agent loop with 500+ iterations, debug cycles, hyperparameter sweeps, architecture search. 24h GPU This is what MLE-bench does — and what we explicitly exclude to isolate Architecture judgment from Engineering stamina.
This is the ArchitectureIQ "probe" paradigm: The model gets rich offline data (pre-computed curves for multiple candidates), can run a few small verification experiments, and must make a one-shot decision about which architecture is best. This mirrors how experienced ML practitioners actually work — they don't grid-search; they look at data stats, recall past experience, maybe run a quick sanity check, then commit to a design.

📋 Feasibility: Adapting MLE-bench Tasks to the Probe Paradigm

FactorMLE-bench ConstraintArchitectureIQ AdaptationVerdict
Single Train Cost AIDE runs ~500 nodes in 24h → ~3 min/node avg. Most Low tasks: 1–5 min GPU / seconds CPU. Easily fits probe budget. A 5-probe limit with 5-min GPU runs = 25 min total. Entirely reasonable. Feasible
Offline Pre-computation No offline results; agent starts from scratch each time. We pre-run 5–10 candidate architectures per task, collect GT curves, and present them as "prior knowledge." This is the core of our pipeline. Natural Fit
Contamination Kaggle public leaderboards, top notebooks, GitHub solutions — LLMs may know winners. Mitigated by: (1) No internet access for the model; (2) Skip the most famous competitions (Titanic, MNIST, etc.); (3) Use competitions where the relative ranking of architectures, not the absolute winner, is the question. Even if Claude knows "ResNet is good for dogs," it may not know "ResNet-18 vs EfficientNet-B0 on this specific split." Manageable
Diversity NLP, CV, tabular, audio — covers real ML domains. Complements synthetic data. Real tasks bring "practitioner's intuition" into the benchmark — models must reason about domain-specific structure (spatial locality in images, sequential patterns in text). Value Add
GT Reliability Single split; no multi-seed; human leaderboard noise. We run multi-seed GT per candidate architecture (our existing pipeline). The Kaggle leaderboard is only used for task selection, not for MCQ answer key. Solved by AQ Pipeline

💡 Revised Recommendation

Revised assessment: MLE-bench tasks can be adapted to ArchitectureIQ's probe paradigm, but with careful curation. The key is to shift from "agent does everything autonomously" to "agent sees pre-computed results + can probe, then decides one-shot."
ApproachWhat we doEffortRisk
1. Curate 5–10 Low-complexity tasks Pick tasks without famous public winners (avoid Titanic, MNIST, CIFAR-10). Pre-compute 5–8 candidate architectures per task. Generate offline curves. Convert to MCQ with probe budget. Medium Low-Med
2. Add "synthetic realistic" tasks Generate synthetic datasets that mimic real structures (spatial correlation, feature interactions, sequential patterns). More diversity, zero contamination. Medium Very Low
3. Keep pure synthetic families The 5 existing dataset families remain the core. They are the cleanest test of architecture reasoning. Done None
Paper narrative: We can frame ArchitectureIQ as sitting between two extremes — (a) pure synthetic reasoning benchmarks that are too OOD, and (b) real-world agent benchmarks (MLE-bench, MLAgentBench) that conflate engineering with judgment. Our probe paradigm isolates the architecture intuition that experienced practitioners use: look at data properties, recall patterns, run a quick sanity check, then decide. This is a distinct capability from both "reciting memorized Kaggle solutions" and "iterating 500 experiments."

LLMs as In-Context Meta-Learners (CASH)

22 Kaggle tabular tasks. Model + Hyperparameter joint selection. Source: arxiv 2510.26510 (NeurIPS 2025)
SettingDescriptionPerformance
Zero-Shot LLM gets only task metadata (dims, samples, stats), no prior examples Surprisingly effective; competitive with HPO baselines
Meta-Informed Adds k prior (metadata → config) pairs as in-context examples Outperforms Zero-Shot & classical HPO
Synthetic Ridge Controlled experiment: predict optimal λ for Ridge regression Meta-Informed with k=100 approaches optimal; outperforms context-only
Model families considered: Logistic Regression, SVM, Random Forest, XGBoost, Neural Network. No neural architecture-level search — only traditional ML model selection. One-shot (no iterative feedback), which is closest to ArchitectureIQ's MCQ paradigm.
